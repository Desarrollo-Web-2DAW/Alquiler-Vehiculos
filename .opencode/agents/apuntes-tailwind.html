10. Formularios

Un formulario bien hecho tiene tres cosas: etiquetas visibles y asociadas al campo (for e id), estados claros (foco, error, desactivado) y distribución adaptable. Cada campo se envuelve en un bloque .campo que agrupa etiqueta, control y mensaje.

Clases base para campos de texto: w-full rounded-lg border border-gray-300 px-3 py-2 focus:border-indigo-500 focus:ring-2 focus:ring-indigo-200 focus:outline-none disabled:bg-gray-100 aria-[invalid=true]:border-red-500

11. Formulario con validaciones

La validación combina tres capas: atributos HTML (required, minlength, pattern, type="email"), una pequeña función JavaScript que comprueba cada campo y muestra el mensaje, y clases de Tailwind que cambian el aspecto del error.

El formulario usa novalidate para que sea nuestra función la que muestre los mensajes, en lugar del aviso nativo del navegador. Prueba a dejar campos vacíos, escribir un correo sin arroba o contraseñas distintas.

Qué enseña este ejemplo: la función checkField sirve para cualquier formulario con data-validate. Solo hay que añadir atributos y un elemento .msg dentro de cada .campo. Las clases aria-[invalid=true]: pintan el error sin escribir CSS.

13. Plantillas y recursos

Una plantilla es una web o una sección ya diseñada que se adapta a tus textos e imágenes. Con Tailwind, la mayoría de plantillas son bloques de HTML que puedes copiar a tu proyecto.

Comprueba siempre la licencia de cada plantilla antes de usarla en un proyecto real, y revisa que las URLs sigan activas.

13.2 Cómo usar una plantilla

  1. Elige un bloque que se parezca a lo que necesitas (hero, precios, formulario).
  2. Revisa la licencia y si incluye imágenes con derechos.
  3. Copia solo la sección, no toda la página, y pégala en tu HTML.
  4. Sustituye textos, enlaces e imágenes por los tuyos.
  5. Unifica la paleta: si la plantilla usa indigo y tu marca es verde, cambia todas las clases de color a emerald.
  6. Prueba el responsive en móvil, tablet y escritorio antes de dar el trabajo por terminado.
